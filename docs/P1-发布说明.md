# P1 发布与 P0 隔离说明

## 访问与源码

| 版本 | 网页 | 源码 | 版本标签 |
| --- | --- | --- | --- |
| P0（保持原版） | <https://warrrm.github.io/chem-gemini/> | `main`、`p0-stable` | `v1.0.0-p0` |
| P1 | <https://warrrm.github.io/chem-gemini/p1/> | `p1-release` | `v1.1.0-p1` |

P0 固定在提交 `7915a15d368091937cbaf92a08ceac038dfa48d0`。P1 不合并到 `main`，不覆盖 P0 分支、标签或资源文件。P1 网页标题和 DOM 入口均带有 P1 标记。

## 发布机制

GitHub 一个仓库只有一个 Pages 站点，所以采用“一次发布，两套目录”：

```text
站点根目录 /chem-gemini/       ← 原 P0
├── index.html、assets/        ← P0 固定源码的构建结果
├── release-manifest.json     ← 两版提交和 P0 文件 SHA-256
└── p1/                       ← 独立 P1
    ├── index.html
    └── assets/
```

`.github/workflows/p1-pages.yml` 只在 `p1-release` 推送或手动运行时发布。它执行：

1. 安装依赖，校验化学数据，运行单元测试。
2. 构建并测试本机 P1，全部 AI 请求使用模拟响应。
3. `npm run build:pages` 构建静态 P1，资源 base 为 `/chem-gemini/p1/`。
4. `npm run test:pages` 验证静态版标记、密钥边界、离线教学链路及自备 API。
5. 检出固定 P0 提交并构建，不读取 P1 修改后的教学代码。
6. `npm run assemble:pages` 把 P0 原样放在根目录，把 P1 放入 `p1/`；检查 P0 字节完整性、版本标记和子目录路径，拒绝互相覆盖。
7. 上传静态构建产物并部署 GitHub Pages。

旧的单版本 `Deploy to GitHub Pages` 工作流在新版成功部署后停用，避免它单独重发 P0 时删除 P1。后续更新 P1 请推送 `p1-release`，不要运行旧发布工作流。Pages 的 `github-pages` 环境仅需额外允许 `p1-release`，不必把环境部署权限开放给任意分支。

## 密钥与线上识图限制

- 本机 `.env.local` 不提交到 GitHub，也不进入 Pages 构建产物。
- 本机 `npm run dev` / 普通 `npm run preview` 仍可通过 Node 网关使用默认 DeepSeek Key。
- GitHub Pages 是静态托管，不能执行 Node 网关。静态版默认使用空的自备 Key，明确显示说明，并禁用不存在的内置密钥连接。
- 线上可直接体验内置样例、本地搜索和完整化学学习流程；真实在线识图需用户明确填写自备 API Key，且接口必须允许浏览器 CORS。此处不承诺官方接口一定允许浏览器跨域。
- 如需学生无 Key 直接在线识图，必须另外部署带鉴权、配额、限流和 TLS 的服务端；不要把共享默认 Key 硬编码到前端。
- 更换接口会清除旧 Key、撤销图片授权。自备 Key 仅保存在当前标签页 sessionStorage；图片发送前仍需同意。

## 本机验证和预览

```bash
npm ci
npm run validate:data
npm test
npm run build
PLAYWRIGHT_PORT=4187 npm run test:e2e
npm run build:pages
npm run test:pages
npm run preview -- --mode pages --port 4186 --strictPort
```

静态预览地址：<http://127.0.0.1:4186/chem-gemini/p1/>。

上线后可直接针对最终网页重复静态验收，不启动本机服务、不调用真实付费接口：

```bash
PLAYWRIGHT_BASE_URL=https://warrrm.github.io/chem-gemini/p1/ npm run test:pages
```

本轮新增版本隔离与静态密钥测试后，单元测试共 63 条；本机版浏览器场景 17 个，静态版 4 个。真实复杂照片准确率和摄像头权限兼容性不由上述模拟测试保证。
